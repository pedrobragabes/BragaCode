# Catálogo de capacidades e oportunidades

Inventário do briefing recebido em 29/09/2026, ligado ao [master plan](16-master-plan-2026-2028.md) e à [auditoria](15-auditoria-ecossistema.md). A numeração 1–86 preserva a origem para permitir conferência. Os dois primeiros itens são diretrizes; os demais misturam serviços, produtos, módulos e canais.

## Como ler

- **Direção:** regra de posicionamento/arquitetura proposta neste plano.
- **Oferta:** a categoria já aparece no catálogo BragaCode; cada serviço depende de diagnóstico e escopo. Não comprova um produto padronizado pronto.
- **Base:** há código ou demonstração nos três projetos auditados; o produto completo ainda tem aceites próprios.
- **Hipótese:** oportunidade futura ou referência externa não auditada. Não inferir prontidão por existir um nome/protótipo em outro projeto.

Famílias comerciais: **Web**, **Commerce**, **Sistemas**, **Automação**, **Infraestrutura** e **IA**. Design/conteúdo são serviços complementares. F1–F6 são as fases condicionais do master plan; não representam disponibilidade nem compromisso de data. A mesma capacidade pode entrar como serviço sob proposta antes de virar produto.

## Composições que evitam duplicação

| Oferta | Composição | Fronteira que deve permanecer |
| --- | --- | --- |
| Site / landing / campanha | Conteúdo + identidade visual + formulário + SEO + hospedagem | Reutiliza implementação, mas cada cliente tem conteúdo e autorização próprios. |
| Catálogo / loja | Catálogo + tema; carrinho/pedido/pagamento quando contratados | Item informativo BES não se torna saldo de venda. |
| Delivery / PDV / cozinha | Catálogo + estoque + pedido + pagamento + operação específica | Caixa, preparação e logística estendem o domínio; não duplicam o pedido central. |
| CRM / orçamento / OS | Cliente + lead + proposta + tarefa + documento | Atendimento comercial não concede acesso financeiro ou administrativo ao tenant. |
| Agenda / reservas / check-in | Recurso + disponibilidade + confirmação + notificação | Evitar dupla reserva exige regra própria, diferente da reserva de SKU. |
| WhatsApp / marketplace / ERP | Adaptador + contrato + credencial + idempotência + reconciliação | O canal não vira nova fonte de verdade por acidente. |
| Signage / menu TV / chamada | Mídia + publicação + player + agenda | Dispositivo é cliente autorizado, não administrador da loja. |
| Hospedagem / manutenção / backup | Ambiente + observabilidade + recuperação + suporte | O plano de serviço deve corresponder à operação realmente assumida. |

## Critério para promover uma hipótese

Selecionar uma oportunidade só após registrar problema recorrente, consumidor/piloto autorizado, dono do domínio, capacidade reutilizada, custo operacional, critério de sucesso e saída/rollback. Reconsultar issues para reutilizar escopo existente. Quando faltar evidência, manter como hipótese; não abrir dezenas de issues apenas para espelhar esta tabela.

As prioridades de produto não substituem o trabalho próprio do CadastraFácil nem autorizam alterações incidentais em outros repositórios. A promoção de uma linha deste catálogo para oferta pública exige evidência técnica e condições comerciais verificadas.
